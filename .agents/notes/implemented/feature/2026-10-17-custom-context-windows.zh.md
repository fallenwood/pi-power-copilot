# Agent Note: 按模型配置低于服务上限的上下文窗口

Status: implemented

[English](2026-10-17-custom-context-windows.md) | 中文

## Problem

发现的模型目录始终暴露服务端的最大上下文窗口。用户无法为各个模型选择任意更小的 token 预算，除非使用不校验服务端上限的通用模型覆盖配置。

## Decision

扩展在注册时读取 Pi agent 配置目录中的 `power-copilot.json`。其中可选的 `contextWindows` 对象将精确模型 ID 映射到严格小于各模型发现上限的正安全整数 token 数，不限制预设档位或步长。缺少配置或未配置的模型保留原始上限。不可用模型的配置条目保持未启用状态，直到模型发现提供其上限。

配置语法、结构和整数错误会明确导致注册失败。上限错误通过模型刷新报告，包括离线缓存恢复，而同步模型读取不会抛出异常。成功发布的目录为 Pi 的模型列表、选择和上下文统计提供生效窗口，覆盖两种认证方式及所有支持的 API。输出 token 上限和其他能力保持不变。

Pi 的目录缓存保留未经修改的服务端上限；只有发布的内存视图使用配置窗口。配置修改在重启后生效，调大或删除覆盖值也适用于离线缓存目录。发布继续使用 Pi 的代次和取消校验。OAuth 续期保持与配置校验和模型发现独立，参见[续期决策](../../bug-fix/2026-10-02-independent-oauth-renewal.zh.md)。

## Alternatives considered

- 仅使用 Pi 的 `models.json` 覆盖配置：该机制已能替换上下文元数据，但不强制校验发现的最大值，因此无法提供所需的校验。
- 将缩小的窗口持久化为目录上限：不采用，因为后续离线会话会丢失原始最大值，无法可靠地调大或删除覆盖值。
- 在每次同步模型读取时计算覆盖值：不采用，因为 Pi 要求模型读取不抛出异常，否则可能将校验错误隐藏为空目录。

## Consequences

扩展新增 provider 专属配置文件，不改变凭据或目录存储格式。无效的刷新会报告错误并保留最后成功发布的目录。极小窗口也会被接受，但可能不适合 Pi 当前的压缩预留或提示词大小；此设置不会扩大服务容量，也不保证请求成功。通用的 `models.json` 覆盖配置仍是 Pi 的后置配置层，不应同时设置同一上下文窗口。

回归测试覆盖任意整数预算及精确边界、格式错误的配置、两种认证方式、所有 API 路由、原始缓存保留、离线调大和删除，以及明确的刷新错误。英文、中文和翻译元数据版本保持一致的结构和决策。
