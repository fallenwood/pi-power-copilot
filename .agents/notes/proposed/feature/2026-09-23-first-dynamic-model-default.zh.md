# Agent Note: 使用动态发现的第一个模型作为默认模型

Status: proposed

[English](2026-09-23-first-dynamic-model-default.md) | 中文

## 问题

Power Copilot 认证成功后，Pi 提示 `power-copilot` provider 未配置默认模型。该 provider 动态发现模型目录，因此无法在认证前声明与账户相关的首个模型。

## 提案

认证成功后，刷新经过认证的 Power Copilot 模型目录；仅当会话尚未选择模型时，使用首个可用模型作为默认模型。通过 Pi 支持的 API 持久化该选择，使其在后续会话中仍为默认模型。OAuth 和 API key 认证均采用此行为。如果发现模型失败或没有可用模型，则保留认证成功状态，并提示用户运行 `/model`。

此方案需要 Pi 核心支持从动态刷新的目录中选择 provider 默认模型。当前 provider 扩展 API 未提供向 Pi 登录后模型选择逻辑注册默认模型的方式。

## 考虑过的替代方案

- 继续要求用户通过 `/model` 选择：兼容当前 API，但不满足自动设置默认模型的需求。
- 硬编码模型 ID：因模型目录是动态的且会随账户变化而被否决。
- 由扩展修改 Pi 内部默认 provider 映射：因这不是受支持的扩展 API，且会让插件依赖 Pi 内部实现而被否决。

## 验收标准

- OAuth 和 API key 登录在尚未选择模型时，使用经过认证的目录中的首个可用模型。
- 通过 Pi 支持的 API 将所选 provider 和模型持久化为默认值。
- 不覆盖已有的模型选择。
- 目录为空或无法获取时，不撤销成功的认证，并保留通过 `/model` 手动选择的方式。

## 风险

- 目录刷新失败不能被报告为认证失败。
- 按目录顺序选择会让服务端模型排序成为可见行为；服务端排序变化可能改变默认模型。
- 在 Pi 提供受支持的登录后默认选择钩子或等效配置前，无法仅在扩展中安全地完成此功能。
